# weightop
Comment system with different deploy variants: from simple app to high-load app

## Технологический стек

| Технология | Версия | Назначение |
|------------|--------|------------|
| Java | 25 | Язык программирования |
| Spring Boot | 4.1.1 | Веб-фреймворк |
| Gradle | 8.14+ | Система сборки |
| OpenAPI Generator | 7.23.0 | Кодогенерация из спецификации |
| springdoc-openapi | 3.1.0 | Swagger UI для просмотра API |
| Jakarta Validation | — | Валидация входных данных |

## Архитектура

Проект построен по принципу **API-first**:
1. Единственный источник правды — `openapi.yaml` (в `src/main/resources/`).
2. Из него автоматически генерируются:
    - **DTO** (модели запросов/ответов) — пакет `com.weightop.model`
    - **API-интерфейсы** — пакет `com.weightop.api`
3. Разработчик вручную пишет только реализации контроллеров.

```
openapi.yaml → [openapi-generator] → DTO + API-интерфейсы → [compileJava]
```

## Методы API

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/v1/comments` | Создать комментарий |
| GET | `/api/v1/comments/{commentId}` | Получить комментарий по идентификатору |
| PUT | `/api/v1/comments/{commentId}` | Обновить текст комментария |
| DELETE | `/api/v1/comments/{commentId}` | Удалить комментарий |
| POST | `/api/v1/comments/{commentId}/like` | Увеличить количество лайков на 1 |
| DELETE | `/api/v1/comments/{commentId}/like` | Уменьшить количество лайков на 1 |
| GET | `/api/v1/posts/{postId}/comments` | Получить комментарии к посту (пагинация) |

## Схема базы данных (MVP)

### Таблица `comments`

| Поле | Тип         | Ограничения | Описание                             |
|------|-------------|-------------|--------------------------------------|
| `id` | BIGINT      | PRIMARY KEY, NOT NULL | Уникальный идентификатор комментария |
| `author` | BIGINT      | NOT NULL | Идентификатор автора                 |
| `post_id` | BIGINT      | NOT NULL | Идентификатор поста/статьи           |
| `text` | TEXT        | NOT NULL | Текст комментария (до 1000 символов) |
| `likes` | INTEGER     | NOT NULL, DEFAULT 0, CHECK (likes >= 0) | Количество лайков                    |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | Время создания (UTC)                 |
| `updated_at` | TIMESTAMPTZ | NULL | Время последнего обновления текста   |

### Индексы

| Индекс | Тип | Поля | Назначение |
|--------|-----|------|------------|
| `comments_pkey` | B-tree | `id` | Первичный ключ, быстрый поиск по ID |
| `idx_post_created` | B-tree | `post_id ASC, created_at DESC` | Основной индекс для выгрузки комментариев поста по дате (новые сначала) |
| `idx_post_likes` | B-tree | `post_id ASC, likes DESC` | Опциональный индекс для сортировки по популярности (топ комментариев) |

### Правила пагинации

- **Метод**: `LIMIT / OFFSET` на основе индекса `idx_post_created`.
- **Параметры**:
    - `limit` — количество записей на страницу (по умолчанию 20, максимум 100).
    - `offset` — смещение (по умолчанию 0, **максимум 1000**).
- **Сортировка по умолчанию**: по `created_at DESC` (сначала новые).
- **Сортировка по популярности**: по `likes DESC, created_at DESC` при флаге `sort=popular`.
- **Ограничение**: запрещено запрашивать `offset > 1000` (защита от глубокой пагинации).
- **Формат ответа**: массив объектов `Comment` без обёртки.

### Отсутствует (сознательно для MVP)

- Партиционирование (комментарии не архивируются, посты имеют неограниченный срок жизни).
- Реплаи (плоская модель).
- Мягкое удаление (физическое удаление).
- Материализованные представления.
- Полнотекстовый поиск.

### Оценка роста (при 50 RPS, 12 комментариев/сек)

| Период | Записей | Размер данных (с индексами) |
|--------|---------|------------------------------|
| День | ~1 036 800 | ~265 МБ |
| Неделя | ~7 257 600 | ~1.9 ГБ |
| Месяц | ~31 000 000 | ~7.9 ГБ |
| 3 месяца | ~93 000 000 | ~23.8 ГБ |

Диск 50 ГБ заполнится за ~6 месяцев, 250 ГБ — за ~2.5 года при постоянной максимальной нагрузке.


## Ограничения MVP

- **Лайки**: только инкремент/декремент на 1, без атомарной защиты от гонок (для текущей нагрузки достаточно).
- **Пагинация**: `LIMIT/OFFSET` — приемлемо для MVP, но при offset > 10000 может замедляться.
- **Идентификаторы**: только UUID (пост, комментарий). Автор — строковый идентификатор.
- **Обновление**: обновляется только текст комментария, остальные поля неизменяемы.
- **Мягкое удаление**: не реализовано, используется физическое удаление.

## Генерация кода

Генерация запускается автоматически перед компиляцией:
```bash
gradle compileJava        # сгенерирует код из openapi.yaml и скомпилирует
gradle openApiGenerate    # только генерация без компиляции
```

Сгенерированный код находится в `build/generated/src/main/java` и **не должен** редактироваться вручную.
